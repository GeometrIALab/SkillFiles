# Pre-circulation checklist

Work through this list before a manuscript leaves the workspace, whether it goes
to co-authors, invited experts, a preprint server or a journal. Record the outcome
in `LOG.md` with the date and the manuscript version, and report every unmet item
to the user. An unmet item is not necessarily a blocker. It must be visible,
though, and must never be glossed over.

## 1. Claims and statuses

- [ ] Every theorem-like environment carries a `% register: R<n>` tag, and every
  tag names an existing entry in the Results register (`PROJECT_SUMMARY.md`).
- [ ] Each environment matches its register status:
  - PROVED: Theorem, Proposition, Lemma or Corollary.
  - PROVED-MODULO: stated conditionally, with the condition explicit. Never
    unconditionally.
  - CITED: cited with its theorem number.
  - CERTIFIED: marked as computer-assisted, with the certificate described.
  - NUMERICAL: an Observation or Remark, or the experimental section. Never a
    theorem.
  - HEURISTIC: labelled as heuristic.
  - CONJECTURE: a Conjecture.
  - UNRESOLVED: not claimed.
- [ ] No `GAP-<n>` marker, `<<placeholder>>`, `TODO` or `??` remains in the text.
  Search the `.tex` source and the PDF.
- [ ] The abstract and introduction claim nothing stronger than the body. Every
  conditional result in the body is still conditional in the abstract.
- [ ] Prose matches status. "We show", "we prove", "it follows" and "we verify"
  appear only for PROVED, CITED or CERTIFIED content.
- [ ] Negative results state their scope.
- [ ] No claim listed as withdrawn in the Corrections table of `HANDOFF.md`
  appears, including in text reused from older drafts.
- [ ] Superlatives ("first", "complete", "sharp", "optimal") are backed by a
  literature search or an attaining example.

## 2. Proofs

- [ ] Every headline result has been independently reviewed (`review: independent`
  or `review: human:<name>` in the register). Any headline result without review
  is listed in the report to the user.
- [ ] Each proof in the paper corresponds to a proof in `PROOF_PROGRESS.md` whose
  status is PROVED. Steps added while writing were checked with the
  `proof-development` verification checklist.
- [ ] Each statement was compared with the version in `PROOF_PROGRESS.md`,
  hypothesis by hypothesis, after it was edited for readability.
- [ ] Every application of a cited theorem in a proof checks that theorem's
  hypotheses explicitly.

## 3. Literature

- [ ] Every reference in the bibliography is recorded as checked against the
  source in `LITERATURE_REVIEW.md`. It exists, and the authors, title, year and
  venue are correct.
- [ ] Every cited result is quoted or paraphrased correctly, with the right
  theorem number, from the version cited (preprint or published).
- [ ] Where the preprint and published versions differ, the paper cites the one
  whose statement it uses, and says so if it matters.
- [ ] No reference was added from memory without going through the
  `literature-review` skill.

## 4. Computations

- [ ] Each computational claim names its run (run ID or manifest), states its
  certification level, and says where the code and data can be found (repository
  and commit, or archive DOI).
- [ ] Every number in the text, tables and figures was copied from run outputs,
  not retyped, and matches them.
- [ ] Every claim presented as computer-assisted is backed by a CERTIFIED run.
  NUMERICAL runs support only observations.
- [ ] Software and versions are stated wherever results depend on them.
- [ ] Counts of work (examples searched, cases checked) give their units and
  scope, and do not add up counts from different ledgers.

## 5. Notation and presentation

- [ ] Every symbol is defined before it is used, and no symbol has two meanings.
- [ ] Notation and conventions match the notation table. Conventions that differ
  from the standard sources are stated explicitly.
- [ ] Every figure is generated by a script in the repository, and its path is
  recorded next to the `\includegraphics`.
- [ ] Cross-references read correctly in the PDF: no "??", and every reference has
  the right name ("Lemma 3.2", not "Theorem 3.2").

## 6. Compilation

- [ ] A full compile cycle was run: LaTeX, BibTeX, LaTeX, LaTeX.
- [ ] `scripts/check_latex_log.py` reports 0 errors: no undefined references or
  citations, no multiply-defined labels, no missing files, no TeX errors, no
  undefined cleveref formats.
- [ ] Overfull boxes above the threshold have been fixed or accepted on purpose.
- [ ] No rerun request remains in the final log.

## 7. Provenance and status

- [ ] The provenance statement is specific about what AI tools did, who checked
  what, and the manuscript's stage, following `provenance-statements.md`.
- [ ] No human review, approval or certification is claimed unless the register's
  review fields record it.
- [ ] The manuscript's stage (working paper, preprint, submitted, accepted) is
  stated correctly, and nothing that has not been refereed is called
  "peer-reviewed".
- [ ] The author list contains only people. Their consent to authorship is a
  matter for the human authors; the agent never assumes it.
- [ ] The target venue's policy on AI assistance has been checked, if a venue is
  known.

## 8. Files and versioning

- [ ] The version label and date on the manuscript match the file name and the
  log entry.
- [ ] The source, `refs.bib`, figures and figure scripts are all in `paper/` or
  referenced from it, and the manuscript can be rebuilt from the repository.
- [ ] Earlier circulated versions are kept (in `archive/` or under version
  control), not overwritten.

## Report template

```markdown
### Pre-circulation check — <manuscript> v<version> — <YYYY-MM-DD>
- Sections passed: 1, 3, 5, 6, 8
- Unmet items:
  - §2: Theorem B (R7) has review: self only.
  - §4: Table 2 numbers not yet regenerated after run 2026-03-02_sweep.
- Decision needed from the authors: <...>
```
